# 测试记录

本页只写**实际观测到的结果**,以及还没测的东西。推测和待办分开列,不混在一起。

## 测试条件

| 项 | 值 |
|---|---|
| 日期 | 2026-11 |
| 主控 | ESP32-C5-DevKitC,芯片 v1.0,16 MB Flash |
| 舵机 | SG90 连续旋转款,GPIO24 |
| 固件 | `c5_power_stages_hb` / `04_remote_power`,ESP-IDF 6.1.1 |
| APK | 2.6(versionCode 11),`com.example.pcpower` |
| 网络 | 开放接入的 Wi-Fi,2.4 G 与 5 G 双频,关联在 **5 GHz / 信道 44**,DHCP 拿到 IPv4 |
| Broker | 公网托管,TLS + 账号 + 主题 ACL,手机与 C5 各用各的账号 |
| 电脑 | Windows 10 测试机(登录前远控一项);Win11 机器待验证 |
| 测试点 | 室内,舵机与笔记本同处一桌,手机走蜂窝网络 |

> 网络环境换一个就可能不一样。**本文只记录上述条件下的结果**,部署到你自己的网络必须重新实测。

| 项 | 结果 | 证据 |
|---|---|---|

## 待验证

| 项 | 为什么重要 | 怎么记 |
|---|---|---|
| **手机指令 → 舵机按到电源键 → 电脑启动** | 整条链路的最终目的,目前**缺完整证据** | 手机先用蜂窝网络,从首页和磁贴各触发一次。记录:发送时间、板端动作日志、回执内容、是否按到键、电脑是否真的启动 |
| 下压/回位分别调节的效果 | 2.6 的核心改动 | 用两组不同设置分别只改下压、只改回位。记录配置值、两段转动时长、是否按到、是否完全松开 |
| 机械重复性 | 连续旋转舵机无位置反馈 | 先悬空检查方向,再在模拟按键上**连续 10 轮**。记录成功次数、回位偏差、有无卡住、有无板子重启。最后装回笔记本实测 |
| 断电、掉线、超时 | 长期待命必须可靠 | 拔插 C5 电源,记录重新上线耗时、旧指令是否触发、新指令是否执行。主动制造回执超时,确认手机显示「结果未知」且不自动再按 |
| Windows 11 登录前远控 | 只在 Win10 上验证过 | 分别记录 Win10/Win11、冷启动与普通锁屏、登录前是否联网、远控能否连入。以电源指示灯、登录界面或远控上线确认真实启动 |
| 磁贴冷启动路径 | 应用进程未运行时也要能发 | 强制停止 App 后点磁贴,确认结果页自动拉起并完成发送 |

## 已知问题

- **正式按钮曾出现「点了舵机没动」**,单次故障,根因未确认。
- 舵机角度按时长估算,同一组参数在不同安装结构下行程不同,不能直接照抄别人的值。
- 手机端凭据是明文存储(应用私有目录 / localStorage),设备丢失需自行更换账号。
